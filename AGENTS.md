# Working on Autohound

Autohound is a local marketplace for car parts, project cars and auctions. Read `README.md` for the file layout.

## Treat the site as live

Unless the owner says a big change is coming, act as if real people depend on the site.

- Never wipe, reset or re-seed live data.
- Never delete accounts, listings, chats, files or databases, and never overwrite `private.json`, without the owner's explicit approval. Password hashes can't be rebuilt.
- Back up data before anything that moves or changes stored files, and confirm copies before removing originals.
- Keep existing data working. If stored files need a new format, migrate them instead of starting over.
- Test both versions before pushing: `server/node-server.js` and Cloudflare (`wrangler pages dev`). Include the flows you touched and an index rebuild.
- Pushing to `main` publishes the site right away. Tell the owner before a risky push.
- If you can't confirm something on the live site, say so.
- Test scripts live in `test_scripts/` (see its README). Put new ones there when you're done with them. Their output goes in `test_scripts/work/`, which git ignores.
- Before committing, run `node scripts/stamp-version.mjs` (the local pre-commit hook does it). It puts a version in `site/index.html` so code loads from `/v/<version>/...` and browsers never keep old files after a push. Imports inside `site/` stay relative so they keep the version.

## Rules decided by the owner

- Everything visual lives in `site/profiles/`, including page HTML in `views.js`. Each profile has a `desktop` and a `mobile` folder, usually changed together, with small differences to suit each. `site/js/profile.js` picks the active profile and loads `mobile` on phones. Tablets get `desktop`. Shared logic in `site/js` must not write page HTML. `profile1` is the original look. `profile3` is the active look: profile2 plus a side menu (Browse market, My listings, Saved, Messages, Account settings, and a red Site inbox for admins; there's no Sell button, selling starts from My listings) under the header line on main pages, not on log in, sign up or code pages. Its header only has Log out, or Log in and Sign up for visitors. Visitors who aren't logged in never see Sell, Saved, Messages, My listings or Account in any menu: only Browse market (every profile hides Sell from visitors). On phones the bottom bar has three buttons: Log out, Messages, Saved when logged in, or Browse, Log in, Sign up for visitors, and the logo line has no buttons. The rest of the side menu is in the waffle menu, and the search row is a waffle button (opens a slide-out menu with the desktop side menu's pages), Map, the search box, and a square magnifying-glass button. The save star on listing windows is small and 15% dark. Text boxes only turn green when clicked (no extra focus frame), and the phone bottom bar has a plain green top line with no glow. `profile2` is the earlier look: neon colors, a simple marketplace layout, every action a real button, buttons at the top right on desktop and in a bottom bar on mobile. Visitors can't switch profiles.
- Layout rule: place things by anchors (the window's left edge, its true center, its right edge, the vertical middle) and size them relative to the window with `clamp()` minimums and maximums, not by fixed pixel distances. In profile3 desktop, `--edge` is the shared spacing from the window's edges (header and side menu use it, so the logo lines up with the menu), `--side-w` and `--search-w` scale with the window, the header is logo and Map anchored left, search on the window's center, account buttons anchored right, all vertically centered, and `--head-h` is measured from the real header (`site/js/app.js`) so the side menu always starts right under it.
- `profile1` theme: black and neon green, early 2000s tuner. White text and titles, green main title and prices, yellow towns, gray counts.
- Text goes in `records/`. Photos, videos and PDFs go in `data/`, using the same layout.
- IDs look like `L.26.11.04.00000`. Folder names are `ID__title`, and `__` only ever separates the two. Titles use `_` for spaces in folder names.
- People see titles with spaces and never see IDs in page text. Usernames can have spaces but never `_`, at signup or login. Folder names store their spaces as `_`.
- People log in with their email. Accounts without one can use their username. New passwords use a random `client_salt` in `private.json`; older accounts keep their username-based salt so they still work. Unknown emails get a made-up salt so the login page can't reveal who has an account. Usernames can't contain `@`.
- Two-step login (an emailed 6-digit code) is optional, off by default, and switched in account settings. It's saved as `"login_codes": true` in `account.json`, needs a confirmed email, and is skipped if the site can't send email, so nobody gets locked out.
- Usernames are 6 to 40 characters. Passwords are 6 to 15. Signup needs an email, saved as typed in `account.json` and the index. It skips the username rules, but can't have spaces. One account per email, ignoring capitals. Emails are private: only the owner sees theirs. After signup the site emails a 6-digit code from support@autohound.online (`server/verify.js`), and confirming it sets `"email_verified": true` in `account.json`. Codes are hashed, last 15 minutes and allow 5 guesses. Confirming is required whenever the site can send email: there's no skip, an account with an unconfirmed email is sent to the confirm page (it can still open account settings to fix the email, or log out), and the server refuses its other changes until the code is entered. Older accounts with no email log in with their username (the login box says "Email or username") and can add an email in account settings, which sends the same code. A confirmed email can't be changed there. Sending uses Resend once the `RESEND_API_KEY` secret exists. Until then signup still works and the site says codes are off.
- Accounts sort into `A` to `Z` folders, plus `_other`. Other crowded folders sort by date with a generic title.
- The search index must always be fully rebuildable from `records/` and `data/`.
- Chats live under the listing. Each person has their own `.jsonl` file, and an attachment is its own line. The template is `attachment, id, text, time`.
- After 7 days with no message, a chat moves to the next `backupN`, and each new message resets the timer. Sold or removed listings keep their chat in both inboxes until then.
- Sold or removed listings move to `records/backups/listings/<date>__listings/` and the matching `data/` folder, sorted by the listing's ID date. Their chats move out first. Older ones move one per visit, and a move cut off partway finishes on a later visit.
- Public text (usernames, listings, and any future comments) goes through `server/wordfilter.js`. By the owner's decision it blocks only the hard-R slur, including look-alike, stretched and spaced-out spellings. All other words are allowed. Private chats are never filtered.
- An account is an admin only while its `account.json` has `"admin": true`. It's toggled by hand, never by the site (Mr. Link and autoZack are admins). Admins see the site inbox in the menu, not on the home page. Every admin button is neon red with the line pattern. On any live listing, admins get a red Admin delete button just above Report; it asks for the admin's own password, then moves the listing to backups like any removed listing, closes its chats, and records `"removed_by_admin": {account, at}` in `listing.json` (`server/admin.js`).
- Email sent to any @autohound.online address goes to the site's own inbox. The `autohound-mail` Worker (`workers/mail-intake.js`, deployed by hand) puts it in `mail_queue`, and `server/mail.js` saves it as `records/inbox/<date>__inbox/E.ID__Subject/message.json` plus `message.eml` in the matching `data/` folder. Email is shown as plain text only, never as HTML.
- Chats for live listings happen in the chat box on the listing page in every profile; sellers pick a buyer there. The messages and the typing box share one fixed-height frame (`.chat-window`): messages fill it and scroll inside, opening at the newest one, and a short typing line sits at the bottom above Attach and Send, with no divider. Sold or removed listings keep their chat page.
- Features belong to every profile: logic in `server/` and `site/js`, with matching views in each profile. Only layout choices, like profile3's side menu and header buttons, are profile-specific.
- Owners can edit a live listing's words, price and details, but not photos, type or category. A new title renames its folder, and its chats and photos move with it. Auctions with bids keep their price.
- Auction pages never show buyers a market value comparison.
- The site doesn't call itself a demo in page text or messages (no demo strips or sample-photo notes). The one exception, by the owner's choice: a red "DEMO" after the AUTOHOUND lettering in profile3's logo, with the logo's scan lines through it.
- Listing pages in every profile: thumbnails sit under the big photo, arrow buttons show on hover (always on phones), and the left and right arrow keys change photos except while typing. Dragging with the mouse or swiping with a finger changes photos too. Desktop has a full screen button in the photo's top right corner (it turns into an exit button); on phones a tap on the photo opens full screen. Swiping, arrows and arrow keys work in full screen, and Escape or the exit button leaves it. In profile3 the seller's button sits right under the photos (no box around it), and the right side runs: title, description, price and town, Admin delete, Save and Report, then the chat, the details, and the price check last. Report is grayed out until it's built.
- Starred listings are called Saved everywhere (page `/saved`; old `/favorites` links redirect). The code still says favorites internally.
- The map page has its heading, a line of info and the key at the top, and the map fills the rest of the window edge to edge with no frame (down to the bottom bar on phones; `fit()` in `site/js/pages/map.js` sizes it).
- The map (`/map`, a Map button between the logo and search bar in every profile) uses MapLibre (saved in `site/vendor/`) with OpenFreeMap's free tiles, recolored by each profile's `mapstyle.js`. No API key. Sellers can drop an optional pickup pin on the sell and edit forms; it's public, saved as `"spot": {lat, lng}` in `listing.json` and `spot_lat`/`spot_lng` in the index, and has to be within `MAP_AREA`. Listings without a pin show at their town (`TOWN_SPOTS`). The five "Example business" pins come from `EXAMPLE_BUSINESSES` in `server/config.js` until business accounts exist.
- The home page shows popular listing windows under the title "Popular" (centered on phones), with only search and price filters (Min and Max boxes side by side, no "to" between them).

## Viewing the site

The owner watches the live site in the Claude desktop app's browser pane. The old sample preview artifact is retired. `scripts/build-preview.mjs` still works if a sample preview is ever wanted.
